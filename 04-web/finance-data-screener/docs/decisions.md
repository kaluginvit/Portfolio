Сюда записываются решения, принятые в ходе разработки.
Цель: не переизобретать в каждой новой сессии то, что уже обсудили.

## Принятые до старта

### Вариант проекта
**Решение:** Вариант C — ИИ-разведчик данных, конкретизирован как финансовый дата-хаб
**Почему:** Наиболее практичный вариант с реальными открытыми источниками данных

### LLM-провайдер
**Решение:** ProxyAPI (gpt-4o-mini) через OpenAI SDK с кастомным base_url
**Почему:** Дешевле прямого OpenAI, совместим с OpenAI SDK, достаточно для планирования
**Альтернативы:** Прямой OpenAI — дороже; Claude API — избыточно для планировщика

### Структурированный LLM-вывод
**Решение:** библиотека `instructor` для строгого JSON без ручного парсинга
**Почему:** Убирает boilerplate, гарантирует схему, обрабатывает retry

### Хранилище финансовых записей
**Решение:** JSONB в PostgreSQL (таблица `records`)
**Почему:** Схема записей различается для MOEX/ЦБ/РБК, JSONB даёт гибкость без потери индексов

### Контейнеризация
**Решение:** 3 сервиса в Docker Compose: postgres, backend, frontend+nginx
**Почему:** Минимально для production-ready, легко поднимается с нуля одной командой

### [Шаг 2] Ручная Alembic-миграция вместо autogenerate
**Решение:** файл `0001_initial_tables.py` написан вручную, без `alembic revision --autogenerate`
**Почему:** autogenerate требует живого подключения к БД; в CI и при первом `docker-compose up` БД ещё не поднята
**Альтернативы:** autogenerate + скрипт прогрева — лишняя сложность для одной миграции

### [Шаг 2] entrypoint.sh запускает миграции перед uvicorn
**Решение:** `sh /app/entrypoint.sh` = `alembic upgrade head` → `uvicorn`
**Почему:** гарантирует что схема актуальна при каждом старте контейнера; idempotent (alembic пропускает уже применённые)
**Альтернативы:** отдельный init-контейнер — избыточно для учебного проекта

### [Шаг 3] SSL verify=False в httpx и feedparser
**Решение:** все HTTP-клиенты в коллекторах работают с `verify=False`
**Почему:** корпоративный антивирус/прокси перехватывает SSL трафик (в т.ч. в Docker); контейнер не доверяет CA прокси. Данные получаемые (MOEX, ЦБ, TASS) публичные и не чувствительные.
**Альтернативы:** добавить CA сертификат в Docker образ — лишняя сложность для учебного проекта

### [Шаг 3] TASS RSS вместо РБК RSS
**Решение:** `RbcCollector` по умолчанию использует `https://tass.ru/rss/v2.xml`; при получении РБК URL — автоматический fallback на TASS
**Почему:** РБК включил Qrator антибот защиту которая блокирует server-side запросы (возвращает 307 + HTML challenge). TASS возвращает 100 записей статус 200.
**Альтернативы:** Selenium/Playwright для обхода бота — избыточно; Interfax (работает, но 25 записей); прямой TASS — выбрано.

### [Шаг 3] Merge секций MOEX ISS по длине
**Решение:** `_parse_iss_response` объединяет секции (`securities` + `marketdata`) если их количество строк совпадает — обновляет dict через `.update()`
**Почему:** MOEX ISS для TQBR возвращает справочные данные в `securities` (SECID, SHORTNAME) и торговые в `marketdata` (LAST, VALTODAY, VOLTODAY) — обе секции по 262 строки в одном порядке
**Альтернативы:** JOIN по SECID — сложнее, медленнее; брать только одну секцию — теряем поля

### [Шаг 3] VALTODAY vs VOLTODAY для фильтрации объёма
**Решение:** для фильтрации объёма торгов в рублях использовать `VALTODAY`, не `VOLTODAY`
**Почему:** VOLTODAY = объём в лотах (маленькие числа); VALTODAY = объём в рублях (миллиарды)
**Как применять:** LLM-промпт должен знать об этом различии

### [Шаг 4] npm install --strict-ssl=false в frontend Dockerfile
**Решение:** флаг `--strict-ssl=false` добавлен в `RUN npm install` во frontend Dockerfile
**Почему:** антивирус перехватывал SSL трафик внутри Docker → `UNABLE_TO_VERIFY_LEAF_SIGNATURE` при скачивании npm-пакетов. После отключения антивируса флаг убран — сейчас Dockerfile без флага.
**Альтернативы:** `.npmrc` с `strict-ssl=false` — эквивалентно; добавить CA сертификат антивируса в образ — лишняя сложность.

### [Шаг 4] docker compose запускать с явным именем проекта
**Решение:** всегда использовать `docker compose -p screener` в этом проекте
**Почему:** путь к проекту содержит кириллицу и пробелы → Docker Compose не может автоматически вывести имя проекта из пути → ошибка "project name must not be empty"
**Как применять:** все команды docker compose в этом проекте: `docker compose -p screener up/down/logs`

### [Шаг 5] AuditMiddleware через BaseHTTPMiddleware Starlette 0.41
**Решение:** `await request.body()` в middleware — Starlette 0.41 автоматически кэширует тело через `_CachedRequest` и переподаёт его downstream через `wrapped_receive`. Нет нужды переопределять `request._receive`.
**Почему:** В Starlette 0.41 `BaseHTTPMiddleware.__call__` создаёт `_CachedRequest`, чей `wrapped_receive` проверяет `_body` и возвращает кэшированное тело. Ручное переопределение `_receive` сломало бы логику disconnect-detection.
**Альтернативы:** ASGI middleware напрямую — избыточно; Depends-based логирование — не покрывает 4xx/5xx.

### [Шаг 5] POST /datasets/{id}/collect принимает agent_run_id
**Решение:** Эндпоинт collect требует `agent_run_id` в теле запроса — берёт план (source, api_url, fields, filters) из уже сохранённой AgentRun записи.
**Почему:** Разделение планирования (POST /ai/plan_and_collect) и исполнения (POST /datasets/{id}/collect) позволяет фронтенду показать план пользователю и дать возможность подтвердить или отклонить, прежде чем запускать сбор.
**Альтернативы:** Передавать план прямо в collect — нарушает Review Flow для needs_review=true.
