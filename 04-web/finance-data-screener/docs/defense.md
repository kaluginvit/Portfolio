## Структура выступления

### 1. Проблема (30 сек)

> «Финансовые данные — MOEX, ЦБ РФ, новости — доступны бесплатно через открытые API. Но чтобы получить нужную выборку, нужно знать конкретный URL, формат параметров, названия полей. Это барьер для большинства пользователей.»

---

### 2. Решение (30 сек)

> «Мы убираем этот барьер. Пользователь пишет запрос на русском языке. Языковая модель сама строит URL, определяет фильтры, объясняет свой план — и только потом запускает сбор.»

---

### 3. Архитектура (1:30)

> «Система состоит из трёх контейнеров, которые поднимаются одной командой.»

**Нарисовать или показать схему из report.md:**

```
Browser → nginx :80 → FastAPI :8000 → PostgreSQL
                           ↓
                      ProxyAPI (gpt-4o-mini)
                           ↓
              MOEX ISS / ЦБ РФ / ТАСС RSS
```

> «Ключевой компонент — LLM-сервис. Используется библиотека instructor, которая заставляет языковую модель вернуть строго типизированный JSON по Pydantic-схеме. Это убирает ненадёжный ручной парсинг.

> Источников три: MOEX для биржевых данных, ЦБ РФ для валют, ТАСС как замена РБК — РБК заблокировал серверные запросы антиботом.

> Все финансовые записи хранятся в JSONB в PostgreSQL. Структура данных у трёх источников разная, JSONB даёт гибкость без потери возможности фильтрации.

> Каждый HTTP-запрос к API логируется в audit_runs через Starlette middleware — незаметно для пользователя.»

---

### 4. Главная особенность: Review Flow (1:00)

> «Важное архитектурное решение — разделение планирования и исполнения.

> Планирование: POST /ai/plan_and_collect — LLM строит план и возвращает его. Фронтенд показывает пользователю, что именно будет собрано.

> Если запрос двусмысленный — например, "акции с хорошими дивидендами" — MOEX не содержит данных о дивидендах. LLM выставляет needs_review=true. Пользователь видит причину, сбор не запускается.

> Исполнение: только после явного подтверждения пользователя — POST /datasets/{id}/collect.

> Это предотвращает бессмысленные или неверные сборы.»

---

### 5. Тестирование (1:00)

> «Две формы тестирования.

> Автотесты: 18 pytest-тестов, 0 предупреждений. Покрыты все API-эндпоинты: health, CRUD датасетов, сбор записей, audit middleware. Тесты используют реальную тестовую БД — не моки — потому что asyncpg привязывает соединения к event loop и mock-тест дал бы ложное покрытие.

> Функциональные тесты: 10 запросов в JSONL — 7 корректных, 2 двусмысленных, 1 невыполнимый. Каждый запрос задокументирован с ожидаемым поведением LLM.»

## Вероятные вопросы и ответы

### «Почему не OpenAI напрямую?»
ProxyAPI дешевле и работает из России без VPN. SDK совместим — только меняется `base_url`. Для простого планировщика gpt-4o-mini более чем достаточно.

### «Что будет если LLM построит неверный URL?»
Коллектор вернёт пустой список или ошибку от источника. Эта ошибка будет записана в audit_runs и отображена пользователю. LLM имеет высокую точность для структурированных URL MOEX/ЦБ — это не свободный текст, а шаблоны.

### «Почему ТАСС, а не РБК?»
РБК включил Qrator антибот-защиту — server-side запросы возвращают 307 с HTML-челленджем. ТАСС RSS работает корректно и возвращает 100 записей.

### «Почему JSONB, а не отдельные таблицы?»
Схема записей у трёх источников принципиально разная: у MOEX — тикер, цена, объём; у ЦБ — CharCode, Value, Nominal; у ТАСС — title, link, pubDate. Унифицированная реляционная схема потребовала бы nullable-колонок или EAV. JSONB гибок и индексируем.

### «Как масштабировать?»
Текущая архитектура — single-node Docker Compose. Для масштабирования: вынести сбор в Celery-задачи (уже заложен разрыв между планированием и исполнением), добавить Redis как брокер, реплики PostgreSQL для чтения. Фронтенд — stateless nginx, масштабируется тривиально.

### «Почему verify=False в httpx?»
Корпоративный антивирус перехватывает SSL-трафик внутри Docker-контейнера. В рабочей среде без перехватывающего прокси verify=True. Данные от MOEX/ЦБ/ТАСС публичные и не чувствительные, риск минимален.

### «Какой следующий шаг для production?»
1. Вынести сбор в фоновые задачи (Celery + Redis)
2. Добавить авторизацию (JWT)
3. Заменить verify=False на корректный CA bundle
4. Добавить rate limiting на эндпоинты LLM
5. Настроить мониторинг (Prometheus + Grafana)
