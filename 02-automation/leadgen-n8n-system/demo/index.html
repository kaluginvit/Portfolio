Engineering Logic
Key patterns from workflow_utils.py — Python mirrors of n8n Code nodes, fully unit tested (43 tests).
🔑
Idempotency Gate (WF-01)
Every incoming event gets a deterministic SHA-256 key computed from its identity fields. Duplicates (same lead seen again within the scan window) are silently dropped before any enrichment or outreach runs.
def make_event_key(event_data, key_fields=None): fields = key_fields or ["id", "source", "url", "company", "email"] parts = [str(event_data.get(f, "")) for f in fields] raw = "|".join(parts).encode("utf-8") return hashlib.sha256(raw).hexdigest()[:16] # Mock payload result: make_event_key({"source": "intent_radar", "company": "Acme Technologies", "email": "alex@acme.example.com"}) # → "e308cb1b5e34d52b"
🌡️
Warmth Decay Formula (WF-06)
Lead "temperature" decays 10% per inactive day. A recent reply boosts warmth by +30 (capped at 100). Warmth bucket drives nurture cadence: hot = immediate, cold = re-activation sequence.
def apply_warmth_decay(warmth, days_inactive, has_recent_reply=False): decayed = warmth * math.pow(0.9, max(0.0, days_inactive)) result = round(decayed) if has_recent_reply: result = min(100, result + 30) return result # Buckets: hot ≥70 · warm ≥40 · cool ≥15 · cold <15 apply_warmth_decay(60, days_inactive=1) # → 54 (warm) apply_warmth_decay(60, days_inactive=7) # → 32 (cool) apply_warmth_decay(60, days_inactive=1, has_recent_reply=True) # → 84 (hot)
🗳️
Multi-LLM Consensus (WF-03)
Three models score the lead independently. Weighted average gives the consensus score. If max−min > 0.3 (30% divergence), the lead is escalated to Human Review rather than auto-approved.
def compute_consensus_score(scores, weights=None): w = weights or [1.0] * len(scores) consensus = sum(s*wt for s,wt in zip(scores,w)) / sum(w) divergence = max(scores) - min(scores) return {"score": round(consensus,3), "agreement": divergence <= 0.3, "divergence": round(divergence,3)} compute_consensus_score([0.82, 0.75, 0.79], weights=[1.0, 0.9, 1.1]) # → {score: 0.788, agreement: True, divergence: 0.07}
⚠️
Error Classification + Retry Policy (WF-10)
All workflow failures route to the Global Error Handler. Severity is classified by first regex match. Critical errors page immediately; warnings batch to Slack digest; info is logged only.
def classify_error_severity(error_message): if re.search(r"timeout|ECONNREFUSED|401|403|5\d\d|fatal", msg): return "CRITICAL" if re.search(r"rate|retry|warn|429", msg): return "WARNING" return "INFO" # Retry policy: # external_api → 3 attempts, backoff [5s, 15s, 45s] # llm_api → 2 attempts, backoff [10s, 30s] → human review # webhook → 5 attempts, backoff [2s…60s] → log & skip

Human-in-the-Loop Design (WF-04)
Two stop-points keep humans in control: (1) before first outreach for all high-value leads, (2) when multi-LLM divergence exceeds 30%. Slack interactive buttons allow approve / edit / reject without leaving the chat.

Shadow Mode Validation (WF-09)
Before promoting a new workflow version to production, it runs in shadow mode on real leads. Results are compared against production output without affecting real outreach. Delta score decides promotion.
# Shadow run flow: 1. New WF version runs in parallel → shadow draft 2.
