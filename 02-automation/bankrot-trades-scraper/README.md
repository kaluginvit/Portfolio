# Парсер торгов Федресурса

## Проблема

Публичные данные о торгах на банкротстве разбросаны по сотням страниц с ASP.NET-пагинацией и Angular shadow DOM — ручной сбор нереален. Стандартные парсеры не справляются с защитой от ботов.

## Решение

Stealth-парсер на [Scrapling](https://github.com/D4Vinci/Scrapling) + Playwright: обходит листинг торгов, открывает карточки лотов, нормализует поля (Описание, Начальная цена, Задаток и др.) и пишет в SQLite. Веб-интерфейс на Flask для ревью и фильтрации базы прямо в браузере.

## Почему такой стек

| Компонент | Почему |
|-----------|--------|
| **Scrapling** | Stealth-режим обходит Cloudflare/JS-проверки; умеет обрабатывать shadow DOM (Angular на fedresurs.ru) |
| **Playwright** | Нужен для ASP.NET postback-пагинации и JS-рендеринга карточек |
| **SQLite** | Zero-deploy, инкрементальная запись, безопасное переключение между сессиями |
| **Flask** | Минимальный UI для ревью без отдельного фронтенд-стека |

## Результат

За один прогон собирает **сотни объявлений о торгах** с полями лотов, сохраняет в SQLite с дедупликацией. Flask-интерфейс позволяет листать, фильтровать и удалять записи без SQL.

## Быстрый старт

```bash
pip install -r requirements.txt
playwright install chromium   # для режима --table (карточки лотов)
```

Запуск парсера:

```bash
python fetch_bankrot_trades.py
python fetch_bankrot_trades.py --date-from 01.01.2024 --date-to 31.01.2024
```

Просмотр базы в браузере:

```bash
python db_review_server.py
# → http://127.0.0.1:3000
```

Тесты (без сети):

```bash
pytest tests/ -v
```

## Скрипты

| Файл | Назначение |
|------|-----------|
| `fetch_bankrot_trades.py` | Основной парсер: листинг → карточки → SQLite |
| `db_review_server.py` | Flask веб-интерфейс для ревью базы |
| `filter_db_delete.py` | Фильтрация и удаление записей |
| `expand_extras_db.py` | Дополнение записей данными из карточек лотов |
| `open_db_urls.py` | Пакетное открытие URL из базы в браузере |

> Соблюдайте `robots.txt` источника и используйте разумные паузы между запросами.
