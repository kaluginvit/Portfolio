# Fedresurs MVP

Инструмент для оценки лотов банкротства по рыночным аналогам.

Читает закладки Chrome с объявлениями Федресурса, загружает JSON через публичный API, нормализует лоты в SQLite и выдаёт оценку по двум сценариям: статистика по рыночным аналогам (P25/P50/P75) и LLM-агент с web-поиском.

## Проблема

Лоты на торгах банкротства выставляются без рыночного контекста: арбитражный управляющий публикует описание и начальную цену, но не сравнивает с рынком. Покупатель должен сам понять — переплачивает он или берёт с дисконтом.

Ручной поиск аналогов на Авито/ЦИАН занимает 30-60 минут на лот. При портфеле из 20-50 активных закладок это неподъёмно.

## Решение

Два независимых движка оценки:

**1. Статистический (fedresurs_mvp.py)** — для квартир: парсит N1 и ЦИАН, собирает цены за м2, считает P25/P50/P75 по аналогам близкой площади, строит `target_price = P25 * area * 0.90`.

**2. LLM-агент (valuate.py)** — универсальный: модель (Gemini / OpenRouter) самостоятельно формирует поисковые запросы через Tavily/Brave/Google, находит аналоги для любого типа актива (квартира, оборудование, транспорт, дебиторка) и возвращает 4 сценария цены.

## Как запустить

**Зависимости:**

```powershell
pip install -r requirements.txt
cp .env.example .env  # заполни ключи API
```

**Синхронизация закладок и базовая оценка:**

```powershell
python .\fedresurs_mvp.py all --limit 15
```

**LLM-оценка одного лота:**

```powershell
python .\valuate.py 23595385-6
python .\valuate.py 23595385-6 --provider brave
```

**Пакетная LLM-оценка всех активных лотов:**

```powershell
python .\valuate_batch.py --limit 20 --dry-run   # предпросмотр очереди
python .\valuate_batch.py --limit 20              # запуск
```

**Поиск рыночных аналогов (только недвижимость):**

```powershell
python .\fedresurs_mvp.py fetch-market --limit 15 --clear
```

**Веб-интерфейс для оценки в браузере:**

```powershell
python .\server.py
# открыть http://localhost:5000
```

## Стек и почему именно так

**Python + stdlib** — минимум зависимостей для парсинга. HTTP-запросы через `urllib.request` без `requests`, чтобы не тащить лишнее в инструмент, который работает локально.

**SQLite** — локальная БД без сервера. Данные нужны только на одной машине, объём не превышает нескольких тысяч лотов. Миграции через `ALTER TABLE ... ADD COLUMN IF NOT EXISTS` — идемпотентны при повторном запуске.

**Gemini / OpenRouter как LLM** — модели с function calling и web search. Gemini 2.0 Flash дешевле при массовой оценке, OpenRouter даёт доступ к альтернативным моделям с reasoning.

**Tavily / Brave / Google / Jina как провайдеры поиска** — провайдер выбирается автоматически по наличию ключей в `.env`. Jina работает без ключа как fallback.

**Agentic loop вместо одного запроса** — модель сама решает, сколько поисков нужно (обычно 2–5). Это важно: для квартиры нужен запрос на цены за м2, для оборудования — запрос на б/у рынок конкретной модели.

**Четыре сценария цены** — quick_lot / wholesale / retail / auction_price — это стандартный подход профессионального оценщика при банкротстве. Покупатель на торгах видит auction_price, но понимает свой exit через retail.

## Текущая логика оценки (статистический движок)

Для квартир считается оценка по найденным рыночным аналогам:

- `market_min = P25(цены за м2 аналогов) * area`
- `market_mid = P50(цены за м2 аналогов) * area`
- `market_max = P75(цены за м2 аналогов) * area`
- `target_price = market_min * 0.90`

Коэффициент `0.90` — запас безопасности для целевой цены покупки, не рыночная оценка.

Порог уверенности:

- `< 3` аналогов: оценки нет, `valuation_required`
- `3–5` аналогов: `confidence=low`
- `6–9` аналогов из 2+ источников: `confidence=medium`
- `10+` аналогов из 3+ источников: `confidence=high`

## Решения по лотам

- `auction_interesting` — для аукциона целевая цена покупки выше или равна стартовой цене
- `overpriced_skip` — стартовая цена выше целевой цены покупки
- `public_offer_wait_until_target` — публичное предложение, цена достигнет целевой в найденный период
- `public_offer_price_reached` — текущая дата попадает в интересный период
- `public_offer_no_target_period` — до конца графика цена не достигает целевой
- `needs_result_check` — приём заявок/торги уже истекли, но результата в связках пока нет
